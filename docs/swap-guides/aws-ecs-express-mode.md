# Swap: IaC — OpenTofu → ECS Express Mode CLI (no IaC)

## Why swap

You want to get a container running on ECS in minutes without writing or maintaining any IaC. AWS's `ecs-cli` or `copilot` handle cluster provisioning interactively. Tradeoff: no reproducible state file, harder to version-control topology, and limited customisation of networking/IAM.

## What changes

| Aspect | Default (OpenTofu) | After swap (ECS Express Mode) |
|---|---|---|
| Provisioning | `tofu apply` | `copilot init` / `copilot deploy` |
| State | S3 + DynamoDB | CloudFormation (managed by Copilot) |
| Customisation | Full HCL | YAML manifest files |
| CI/CD | Tofu steps in GHA | `copilot deploy` in GHA |

## Steps (high level)

1. Install AWS Copilot CLI
2. Run `copilot init` from repo root; answer prompts for each service (`api`, `workers`)
3. Commit the generated `copilot/` manifest directory
4. Replace Tofu CI steps with `copilot deploy --env production`
5. Manage secrets via `copilot secret init` (wraps SSM)

## Files touched

- `copilot/` — new manifest directory (generated by CLI)
- `.github/workflows/deploy.yml` — swap Tofu steps for Copilot steps
- `infra/tofu/` — can be removed or kept as reference

## Env vars

- No changes; Copilot uses the same SSM parameters
